# 改动收尾（中文参考）

> **非执行正文。** Agent / 活镜像只加载英文版 `../change-record.md`。本文件仅作人工对照，不安装到 `~/.claude/rules`、`~/.cursor/rules`、项目 `.cursor/rules`。

纯问答、只读、没产生 diff：下面三项都不用。本文件对应英文版中注释、变更日志、commit 文案的条文。

## 注释

**默认禁止新增或改写代码注释。** 可读代码才是交付物；注释不是。

### 优先用类型与测试，而不是注释

约束用类型系统和测试表达：明确的参数与返回类型、枚举、不可变值、可空/可选类型、校验与断言。**禁止**用「传入合法值」这类注释去补弱类型。

产品 / 架构**契约**（docs、ADR、QuestFlow、schema）写在文档与可强制的代码/测试里——**不写进注释**。禁止把 `docs/*` / ADR 条款抄进 `//`。

### 一律禁止（Agent 常见坏例）

- 复述代码在干什么（「遍历列表」「返回结果」）
- **历史叙述**（谁说过、哪次 PR、哪次 review、「先这样以后再改」时间线）
- 把**一次性反馈**写成常设规则（反例：`// Lauren 说过不要这样做`）
- 给**热路径**、常改业务分支或临时修复写步骤注释（比代码更快过期，也更骗人）
- 为显得认真而补的函数头 / 行内注释
- 在类型、测试或文档已拥有规则时，再复述 docs/ADR 产品契约（「按 docs/27 必须…」「ADR-023 禁止…」）

### 唯一允许（须同时满足）

注释只补充**类型和测试表达不了**的内容。常见：为什么有这个限制、并发或生命周期约定、兼容性承诺。写清前置条件、结果和失败方式（当签名与测试看不出来时）——避免复述代码。

写之前自问：删掉这行，几个月后的人会不会误用 API 或踩已知坑？只有答「会」才写；且须**同时**满足：

1. 类型与测试已经无法强制或演示该点
2. 周围代码预期**极少再动**（稳定面），不是本轮改动的过程说明
3. 一句说清 **why**（或并发 / 生命周期 / 兼容）；不写 what/how；不点人名；不点某次 PR；不粘贴 docs/ADR 段落

允许形态：`// CAS: final failure must return error; never swallow as success`  
禁止形态：`// per Lauren's review` / `// fix yesterday's nil deref` / `// docs/27: perpetual may omit output`

getter、纯透传、与周围同模式的片段：不写。

用户**当条消息**明确要求给某处加注释时，只加那一处；历史叙述与文档契约抄写仍禁止。

## CHANGELOG

仓库有 `CHANGELOG.md` 时，在 `[未发布]` 或 `[Unreleased]` 下追加。中文，写模块、做了什么、1～3 个关键路径。仅文档或规则放文档或维护小节。仓库没有该文件则跳过。

## Commit message（只给文案，不执行 commit / push）

```text
<type>(可选scope): <中文简述>
```

type：`feat` `fix` `docs` `style` `refactor` `perf` `chore` `test`。简述约 50 字，不加句号。多仓库分开写。和未提交的其他改动混在一起时，注明建议 stage 的文件。主题和本轮 CHANGELOG 一致。
