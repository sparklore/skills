# 交付与验收（中文参考）

> **非执行正文。** 活镜像只加载英文版 `../delivery-gate.md`。对用户汇报仍用本文件的中文标题结构。

本文件只规定怎么汇报、什么时候算过。编码和测试怎么做见 `engineering`。复杂任务开工前见 `session-plan`。

## 每步回复

```markdown
### 本步已完成
- 一句话

### 验收证据
- 命令：`<已跑命令>`
- 结果：PASS | FAIL — 摘要

### 验收步骤（可复制）
**前置：** 仓库根、依赖、账号从哪来、哪些环境变量只对当前终端有效。

1. 起什么、不起什么：进程或容器名、端口、谁是入口。会抢端口的写明不要一起起。项目若有本地控制台，写卡片名、点哪个按钮、状态和端口；没有就写命令。
2. 一步一件事。依赖上一步时写「同一终端」或「另开终端」。
3. **期望：** 退出码、字段、页面文字、日志关键字。
4. **若失败：** 最可能原因，看哪个日志，回到哪一步。

### 下一步动作
- FAIL → 只纠偏，同命令重跑，不换题，不进下一步。同一失败症状连续修复 ≤3 次；超限停手，汇报卡点与已尝试；禁止删/弱化测试凑绿（见 `engineering`）
- 同 plan 未完且本阶段 PASS → 下一步 id
- 全 plan PASS → 停，等用户「验收通过」（或 `LGTM` / `验收 OK`）
```

一步一条主指令。已经跑过的命令也写进人可复验的步骤。一行改名、纯格式可收成 1～2 步，仍要有可观察期望。

禁止：只丢一条启动或测试命令；步骤只写进文档；进程没确认在听就让人开页面；失败时让人改无关输入。

用户要求一口气做完时，步间停顿可省。阶段没绿不能算过，收尾该跑的全量不能省。

用户验收指出规则盲区或反复低级错误时：修完后问是否写入对应规则；架构硬闸才进 `skills/sparklore-architecture-gates/`，流程类进 `session-plan` / `engineering` / `delivery-gate` 等，禁止默认塞进 gates。

## 界面

改了用户能看见的页面：写清基址、账号来源、菜单或路由、页上应看见的文字、列、按钮。纯接口以命令输出为准。有没有可见入口，只看 `visible-entry`。

### 验证环（Feature Map → 浏览器 / CDP → 再改）

改 UI 或「页面上看见的行为」时，**先复现再改**。人操作优先走本地控制台顶栏 **「UI 验证环」**（`http://127.0.0.1:7789/ui-verify.html`）：打开地图、启停用户端、检查/重生成地图均点按钮，不要默认教终端命令。地图产物：`sparklore-clients/docs/feature-map.md`（代码生成，禁止手改）。完整点击步骤与验收清单：forge 仓 `docs/38-ops-ui-verify-feature-map.md`。

**可复制步骤：**

1. **定位：** 控制台「UI 验证环」→「打开 Feature Map」，用入口文案 / 请求路径 / 文件名搜到目标行；记下「入口 `file:line` → 方法与路径 → handler `file:line` → 状态」。状态「未注册 / 未解析」只说明差集，**不是**「删即可」的因果结论（见 `audit-evidence`）。
2. **起页：** 验证环页确认用户端在听（可点「启动用户端」）或打开 `http://127.0.0.1:8090`。Agent 用 `cursor-ide-browser`：`browser_navigate` →（已有页则先）`browser_lock` → `browser_snapshot`；需要接口字段时用 CDP `Runtime.evaluate`（`awaitPromise: true`）打同一条地图里的路径。
3. **复现：** 按地图走到可见入口，记录**坏的**证据（截图、snapshot 里的可见文字、或 CDP 返回的 JSON 字段）。复现不到 → **停手不改**，汇报「未能复现」与已试步骤；禁止凭猜测改。
4. **再改：** 只改定位到的那条链；禁止借机大重构、禁止为演示改路由 / 业务硬编码。
5. **验证消失：** 同一入口、同一步骤再走一遍；坏现象须消失。证据与步骤 3 同形（截图 / snapshot / CDP）。若改动触及 JS 字面量请求：在验证环点「重生成地图」（或用户端组同名任务卡），产物进提交；勿默认手敲 `FEATURE_MAP_UPDATE`。

汇报里贴：地图行（或等价引用）→ 复现证据 → 修复要点 → 再复现不到的证据。
