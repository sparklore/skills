# 沟通风格（内部 STE，中文参考）

> **非执行正文。** 活镜像只加载英文版 `../communication.md`。

适用于回复、汇报、文档和交接块；不适用于代码、JSON 和模型输出的数据。

结构格式（`delivery-gate` 标题、`audit-evidence` 表格）管版面；本文件管其中的句子。

## 五条默认

1. **一句话只表达一个关键意思。** 「A，而且 B，但是 C」拆成几句。
2. **一个概念一个术语。** 以 `GLOSSARY.md` 和规则原词为准，不换同义词；新术语首次出现时定义一次，之后保持不变。
3. **主动语态，写清主语。** 写「`LocalRunner` 写入记录」，不写「记录会被写入」。
4. **顺序：结论 → 条件 / 约束 / 风险 → 操作。**
   - 会改变「做不做、怎么做」的风险放在操作**之前**。
   - 每一步内部：条件 → 动作 → 期望结果。
   - 剩余说明（跳过了什么、没检查什么）可以放在结尾。
5. **关键判断标注状态**，四选一：
   - **事实**：跑过命令或读过代码；附 `file:line` 或命令
   - **推测**：未核实的推断
   - **建议**：推荐做法，附一条理由
   - **待核验**：尚未确认；写明要跑什么来确认

   审计场景以 `audit-evidence` 为准：事实 = `G1`/`G2`；推测、待核验 = `G3`。

## 不要求

不执行 ASD-STE100 全部 53 条、不设字数上限、不维护通用词的受控词表。领域术语以 `GLOSSARY.md` 为受控词表（第 2 条）。允许自然衔接，不要写得像机器。

## 可复用 Prompt：技术解释

3. 用主动语态，写清哪个组件做哪个动作。
4. 先写条件、约束和风险，再写操作；每一步按「条件 → 动作 → 期望结果」。
5. 关键判断标注：事实（附 file:line 或命令）/ 推测 / 建议 / 待核验（写明要跑什么确认）。
不要寒暄、背景铺垫和修辞；允许自然衔接。
