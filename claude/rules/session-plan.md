# 会话与 Plan

## Charter（复杂任务开工前）

多文件、架构、数据模型、跨服务、大规模文档，或用户没给可写/禁止路径时，先写：

1. 唯一目标（一句）
2. 可写 / 只读 / 禁止路径
3. 交付物清单
4. 验收命令
5. 模式：Plan only 或 Agent execute

用户说「用默认 charter」或已贴完整 charter，确认一句再开始。用户说验收门时，Charter 与 `delivery-gate` 一起用。

## 签字门（改文件前）

消息含 `Implement the plan`、`按计划执行`、`执行 plan`，或附 `.plan.md` 要求开干：

先输出范围表（会改 | 不会改 | 风险 Top3）、与现有架构决定的冲突、回滚命令，以及 A 范围对吗 / B 验收够吗 / C 可以执行吗。

用户写出 **C=是**（或「可以执行」「开干」「直接执行无需再问」）之前，禁止改文件、commit、执行会改环境的命令。只读可以。批准后不改 plan 文件本身，除非用户要求。

## 一会话一波

带 `Don't stop until you have completed all the to-dos` 的 plan，同一对话最多执行 1 次。第二波起先走上面的签字门，或让用户新开 chat。禁止无 C=是 连续接 3 个以上 `Implement the plan`。

## 换会话指令

用户说「下一步」「新开 chat」「执行指令」「给我指令」，或一波做完要换会话：直接给**已填好**的一块，禁止留 `<占位符>`。

从当前仓库填：目标、可写/禁止路径、交付物、验收命令、≤10 行 state（看变更日志和该任务的进度文档）。末尾写 `C=是；直接执行无需再问。` 提醒新开会话再贴。禁止套别的项目的库名、文档编号或启动命令。
